# note の4役(調査 → 企画 → 執筆 → 品質チェック)

2026-11-08 に決めた(北村さんの依頼「執筆担当とチェック担当を絶対に分ける」)。
Instagram の朝の4役(`marketing/roles/`)と同じ形を、note の記事に使う。違いは2つ。

- **毎朝は動かさない。記事を1本作るときだけ、4役を順番に動かす**(note は2週に1本のストック型)
- 動かすのは人のいるスレッド(note のスレッド)。4役はそれぞれ**別のサブエージェント(別の文脈)**として起動し、
  前の役の書いたファイルだけを渡す。執筆役とチェック役に同じ文脈を使わない

**チェック役は直さない。** 指摘と合否だけを出し、直すのは執筆役の次の回。1つの文脈が書いて自分で確かめると
「問題ないと思います」しか返ってこない(北村さんの指摘)。

| 順 | 役 | 定義 | 作るもの |
|---|---|---|---|
| 1 | 調査 | `roles/research.md` | `1-research.md`(確かめた数値と出典、確かめられなかったもの) |
| 2 | 企画 | `roles/planning.md` | `2-plan.md`(読者・検索語・見出し・3本のつながり) |
| 3 | 執筆 | `roles/writing.md` | `3-draft.md`(本文の下書き) |
| 4 | 品質チェック | `roles/qa.md` | `4-qa.md`(項目ごとの合否と指摘) |

## 受け渡しの場所

- 記事ごとの作業フォルダ: `/mnt/project-files/marketing/note/<番号>-<短い名前>/`(例 `01-bodyweight-percent/`)
- 各ファイルの1行目は `状態: 完了` / `状態: 見送り(理由)`。**前の役のファイルが `状態: 完了` でなければ、自分の仕事はしない**
- 品質チェックが合格したら、スレッドの担当が Claude Doc(北村さんが読んで直す下書き)に反映し、リンクを渡す。
  **note への公開は北村さんが行う。** 4役は公開もアカウント操作もしない
- 不合格なら、執筆役が `4-qa.md` の「直すこと」だけを直して `3-draft.md` を書き直し、チェック役(新しい文脈)がもう一度見る。
  同じ記事が2回不合格なら、北村さんの判断を仰ぐ

## 連載の計画(2026-11-08 時点)

自宅で自重トレをする人に向けて、同じ読者が順に読める3本。最初は無料(目的は DL)。

1. 自重トレは体重の何%を持ち上げているか(下書き: https://claude.ai/artifact/GiYRaw5tjww67A7HZDiJYd)
2. 回数が伸びなくなったら次の段へ(自重で漸進性過負荷を進める順番)
3. 余力(RIR)で記録すると何が分かるか

2週に1本。3本そろったらマガジンにまとめる。有料記事は読まれ始めてから考える。

## 自己改善のしくみ

- **学びのノート**: `/mnt/project-files/marketing/note/lessons.md`。4役とも始める前に読む。
  「必ず守ること」(不合格の理由から作った決まり)と「試してよいこと」の2節
- チェック役が、不合格の理由と、2回続けて出た改善提案を「必ず守ること」に1行で足す(〜する / 〜しない、日付)
- 企画役は、前の記事の `4-qa.md` の改善提案から1つを選び、「今回入れた改善」として `2-plan.md` に書く
- 公開後、App Store の `ct=note` の流入と note の閲覧数が分かったら、次の記事の企画に1行で残す。1本で言い切らない

## 全員が守ること

- **エビデンスをもとに有益な情報を提供する。** 釣り・クイズ・煽りは書かない
- 数値は、論文の抄録か本文(表を含む)を**自分で開いて**確かめたものだけ。二次情報(まとめ記事・SNS)しか無い数値は本文に書かない
- 確かめられなかった数値・研究は、本文から外し、記事末尾の「公開前の確認メモ」に理由と一緒に残す
- **体験談を作らない。** 北村さんの体験(アプリを作った理由、自分の記録など)は、北村さんから聞いたものだけを書く。無ければ書かない
- 正確な言葉: 測ったものに合わせる(手にかかる力 / 筋量 / 筋力を混ぜない)。「必ず」「〜で伸びる」と言い切らない
- 順番: 問いかけ(はじめに)→ 研究の答え → 補足・ただし → 何に使えるか → **KURABELLなら(アプリ紹介は最後、機能は1つ)** → 参考文献 → 公開前の確認メモ
- アプリの機能は `index.html` と `src/domain/` で実際にある動きだけを書く
- App Store のリンクは `https://apps.apple.com/app/apple-store/id6816090624?pt=129352960&ct=note&mt=8`
- note は表を表示できない。表は画像にする前提で、本文には表のまま置き、確認メモに「画像にする」と書く
- 文は短く(1文25字前後、長くても50字)、段落は3文まで、北村さんの言葉づかい(です・ます)

## 起動のしかた(スレッドの担当がすること)

Agent ツールで役ごとに1回ずつ、新しいサブエージェントを起動する。プロンプトは次の形で、役の名前とファイルだけ変える。

```
あなたは KURABELL Workout Log の note 記事を作る4役の <役名> 役です。日本語で書きます。
/mnt/project-files/marketing/note/README.md と
同じフォルダの roles/<役のファイル>.md を読み、書かれた手順だけを行ってください。
作業フォルダは /mnt/project-files/marketing/note/<番号>-<短い名前>/ です。ほかの役の仕事はしないでください。
共有フォルダは他のスレッドも使います。書いたファイルは10秒ほどあとに読み直し、消えていたら書き直してください。
パッケージは入れないでください。mcp__hearthbot__ のツールは使わないでください。
最後に、したこと・できなかったこと・北村さんの判断が要ることを3〜6行で報告してください。
```
