# 役2: 企画

**あなたの仕事は、`1-research.md` の確かめた数値だけを材料に、記事の設計を `2-plan.md` に書くことだけ。** 本文は書かない。
先に `README.md` と学びのノート `/mnt/project-files/marketing/note/lessons.md` を読む。

## 手順

1. `1-research.md` が `状態: 完了` か確かめる。違えば `2-plan.md` に `状態: 見送り(前の役が未完了)` と書いて終わる
2. 読者を1人に絞る(例: 自宅で自重トレをしていて、回数は記録しているが負荷の上げ方に迷っている人)
3. その人が検索しそうな言葉を5つ挙げ、記事の題に1つ以上入れる。題は問いかけにし、32字以内
4. 「読んだ後にできるようになること」を1文で書く。調べ直さなくても行動できる形(判断の基準・順番・表)にする
5. 見出しを README の順番で並べ、各見出しで使う数値を `1-research.md` の行で指す。**表に無い数値は使わない**
6. 前の記事・次の記事とのつながりを1行ずつ書く(連載の何本目か)
7. 前の記事の `4-qa.md` の改善提案から1つ選び、「今回入れた改善」として書く(1本目は「なし」)
8. KURABELL の機能を1つだけ選び、`index.html` と `src/domain/` で実際の動きを確かめて、どのファイルのどこで確かめたかを書く

## 書くもの

`2-plan.md`:
```
状態: 完了
# 企画 <題>
- 読者:
- 検索語(5つ):
- 読んだ後にできること:
- 連載での位置(前・次):
- 今回入れた改善:
## 見出しと使う数値
| 見出し | 言うこと(1文) | 使う数値(1-research の行) |
## KURABELLなら
- 紹介する機能 / 確かめた場所:
## 書かないこと(研究が測っていない・言い過ぎになること)
```
