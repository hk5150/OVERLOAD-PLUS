設定タブ「種目の設定」で、部位チップを「その部位でリストを絞り込む」方式から
「該当する見出しへスクロールジャンプする」方式に書き換えた変更(2026-08-19〜20頃)で見つけたパターン。

チップ自体は`allExercises`(内蔵+カスタムの全種目)を母集団に「その部位の種目が1件でもあるか」で表示するため、
ほぼ常に全部位が表示される。一方でジャンプ先の見出し`id="ex-settings-${m}"`は、
実際に画面に描画されている`pool`(既定では「使用中の種目」だけに絞られた集合、検索時は検索ヒットのみ)に
その部位の種目がある場合にしか存在しない。

**Why:** 「チップの表示条件」と「ジャンプ先が実在する条件」の母集団が別物(全種目 vs 絞り込み後のpool)になっていて、
`document.getElementById(...)?.scrollIntoView(...)`のoptional chainingがエラーを握りつぶすため、
不一致時は**サイレントに何も起きない**。ユーザーが「まだ記録していない部位」のチップを押すと無反応になる。

**How to apply:** 「フィルターチップ」を「ジャンプ用ショートカット」に転用するリファクタを見たら、
チップの表示母集団とジャンプ先の存在条件が同じ集合から作られているか確認する。
ずれている場合、多くのユーザーが最初に触る「既定表示(絞り込みなし)」でどれだけのチップが機能するかを
考える(このアプリでは「使用中の種目」だけがデフォルト表示なので、全部位を満遍なく使っているユーザーは稀)。
