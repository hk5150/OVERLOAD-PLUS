KURABELL Workout Log (`index.html`) には、部位(muscle)・器具(eq)などを選ばせる `<select>` が
複数箇所(記録画面のカスタム種目追加パネル×2、設定タブの種目編集モーダル)に**同じ構成のコード片として重複**して存在する。
これらは「プレースホルダーの `<option value="">...</option>` + 実データの選択肢」という形を取っている。

2026-08-19〜20頃のレビューで見つけた不整合: `muscle`は保存時のフォールバックも`""`、
`<select>`のプレースホルダー値も`""`で一貫しているが、`eq`(器具)だけは保存時のフォールバックが
文字列`"その他"`(`eq: meta?.eq || customDraft.eq || "その他"`という行、`addExercise`関数内)なのに、
`<select>`のプレースホルダーは`value=""`( `t("settings.other")`というラベルで表示、値は空文字)。
つまり「器具を選ばずにカスタム種目を追加する」と`eq:"その他"`という値が保存されるが、
後でその種目を編集しようとすると`<select value={e.eq || ""}>`に渡る値`"その他"`と一致する
`<option>`が存在せず、選択状態が崩れる。

**Why:** `customDraft.eq`の初期値がかつて`"ダンベル"`固定だったため、この分岐(フォールバックの3項目め)は
実質到達不能だった。デフォルトを`""`に変える修正(器具の初期値バグ修正)によって、このフォールバックが
日常的に到達するようになり、既存の潜在バグが表面化した。

**How to apply:** `<select>`+空文字センチネルのUIパターンが出てきたら、
「保存時にどのフォールバック値が使われるか」と「対応する`<select>`の`<option value=...>`一覧」を
突き合わせて、**保存され得る値の集合 ⊆ optionのvalue集合**になっているか確認する。
特にこのアプリは同じ構成の`<select>`ブロックを複数箇所に手でコピーしているため(共通コンポーネント化されていない)、
1箇所だけ直して他が古いままという事故が起きやすい。関連: [[kurabell-chip-jump-pool-mismatch]]
