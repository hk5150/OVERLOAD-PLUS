# 履歴の編集

## 後から足した種目が保存されない(2026-10-31 修正)

北村さんの報告「履歴画面で記録し忘れた種目と記録を後から追加したが保存できない」。

**原因**: `saveEditWorkout` は、回数が入っていても余力(RIR)が空欄のワーキングセットを「まだやっていない」として捨てる
(今日の記録の保存と同じ規則)。「記録し忘れた種目を追加」で足した種目は余力が空欄で始まるので、重量と回数だけ入れて
保存を押すと、種目ごと黙って消えていた。全部のセットが空欄だと「有効なセットがありません。この記録を削除しますか?」まで出た。

**直し方(決めたこと)**:
- 余力を自動で埋めることはしない(CLAUDE.md「RIRが入って初めて実施済み」を崩さない)
- 捨てずに保存を止める。回数>0・ウォームアップでない・余力が空欄のセットがあれば、その余力欄を赤枠(`aria-invalid`)にし、
  編集カードの上に「余力が空欄のセットがあります。余力を入れるか、✕でセットを消すと保存できます。」を出す(`history.rirMissing`)
- 回数0のセットは従来どおり黙って消す(ヒントの「回数を0にすると削除」のとおり)
- 止める条件は保存時のフィルタと同じ式から回数0を除いたもので、止めずに捨てる/永久に保存できない組み合わせは無い(レビューで確認)

**確かめたこと**: Web(8765)で、サイドレイズ 8kg×12 を余力なしで足して保存 → 以前は消えていた/今は止まって赤枠。
余力を入れて保存すると記録に入る。iOS シミュレータ(iPhone 17 Pro / iOS 26.5)でも同じ表示を確認し、
✕で空欄のセットを消すと保存でき、アプリを終了して開き直しても追加した種目が残っていた(SQLite)。

**挙動が変わる点**:
- 「+セット」を押しただけで使わなかった行(直前の回数を引き継ぐ)は、以前は黙って捨てていた。今は保存が止まり、✕で消す
- 余力の無いセットが保存済みの記録(バックアップの復元で範囲外の RIR が消えた場合など)を編集すると、
  触っていないセットでも保存が止まる。以前はそのセットが黙って消えていたので、記録を失うよりは良いと判断

**残課題**: シミュレータは iOS 26.5 で確認した。iOS 27 の実機では未確認(次の TestFlight で見る)。
