# 休憩タイマーの通知と Live Activity

休憩タイマー(インターバル)を、アプリを閉じていても・ロック中でも・集中モード中でも
気づけるようにするための仕組み。経緯は [docs/vite移行.md](vite移行.md) の v96(ローカル通知化)・
v109(通知音)・v112(本書の内容)の各節。

## 全体像

| 経路 | 何をするか | どこで |
|---|---|---|
| ローカル通知 | 開始から1・2・3分後に通知(ID 4201〜4203) | 予約: 自前プラグイン `RestTimer`。キャンセル・配信済み削除・許可: `@capacitor/local-notifications` |
| Time Sensitive | 上の通知を集中モードでも届くようにする | `RestTimerManager.schedule`(`interruptionLevel = .timeSensitive`) |
| Live Activity | ロック画面・Dynamic Island に経過時間を常時表示 | 拡張ターゲット `RestActivity`、同期は `RestTimerManager.syncActivity` |
| `beep()` | 通知を許可していない端末・Web版で、アプリを開いている間だけ音 | index.html |

JS 側はすべて `src/domain/restNotifications.js`。Web 版ではネイティブ部分がすべて何もしない。

## 判断

### 通知の「予約だけ」を自前プラグインに移した

`@capacitor/local-notifications` 6.x は `interruptionLevel` を扱えず、Time Sensitive にできない。
node_modules へのパッチは仕組みが無く(gitignore、patch-package なし)、プラグイン丸ごとの置き換えは
影響が大きい。そこで**予約だけ**を自前で行い、IDは同じ文字列("4201"等)にした。

- LocalNotifications のキャンセル・配信済み削除は ID を文字列化して `UNUserNotificationCenter` に渡すので、
  自前で積んだ通知もそのまま消せる(ソースで確認済み)
- 前面にいるときの表示(willPresent)は、知らない ID でも `[.badge, .sound, .alert]` で出る
- RestTimer が無い・失敗したときは LocalNotifications に切り戻す(Time Sensitive にはならないが届く)。
  ネイティブ側は1件でも読めない通知があれば reject し、黙って0件にしない

音も `UNNotificationSound.default` を正式に指定できるので、v109 の「存在しないファイル名 `"default"`
で既定音に落とす」経験則は RestTimer 経由では使っていない(切り戻し用に残してある)。

### Time Sensitive は休憩通知だけ

エンタイトルメント `com.apple.developer.usernotifications.time-sensitive`(`ios/App/App/App.entitlements`)。
Apple への申請は不要(Critical Alerts とは別物)。**ユーザーが自分で始めたタイマーの経過**という、
HIG が想定する典型的な用途に限る。宣伝やお知らせなど、他の通知には絶対に付けないこと。

ユーザーが反応しないでいると、iOS が「時間確定通知を今後も許可しますか?」と聞いてくることがある。
3回がうるさいと言われたら `REST_NOTIFY_MINUTES` を減らす。

### Live Activity は常にオン、状態を合わせる API 1本

- アプリ内に設定は無い(ユーザーの決定)。止めたい人は iOS の設定アプリ → KURABELL → ライブアクティビティ
- ネイティブ API は開始/終了の2本ではなく `syncActivity({startedAt|null, staleAt, title})` の1本。
  同じ値で何度呼んでも結果は同じ。`startRest` は onBlur から連続で呼ばれ、effect も何度も走るため、
  2本に分けると二重作成やちらつきの原因になる
- 同期は index.html の `[loaded, restStartAt, lang]` の effect だけ。`loaded` 後の初回で前回の残骸も
  片付く(下書きから同じ値が戻れば何もせず、無ければ終了)
- **前面復帰では同期しない**。ロック画面でスワイプして消した表示を勝手に復活させないため
- ラベル(インターバル/Rest)は JS から渡す。アプリ内の言語設定に追従させるため、拡張側の
  Localizable は使わない
- 経過表示はシステムが描く `Text(timerInterval:)` と `ProgressView(timerInterval:)` だけで組む。
  アプリが止まっていても(強制終了後も)数え続ける。毎秒 update はしない

### 放置対策は30分

Live Activity はアプリが動いていないと自分で終われない(システム上限は8時間)。
`staleDate = 開始 + 30分`(`REST_ACTIVITY_STALE_MINUTES`)。stale になると拡張側は動く数字をやめ、
灰色の「30:00+」を出す。30分以上たった `restStartAt` で同期されたら終了させる。

### iOS バージョン

- App 本体は iOS 15.0 のまま。Live Activity は **iOS 16.2+**(`ActivityContent`・`staleDate` が使える版)
- App 側は ActivityKit を **Optional(弱リンク)** にし、使うコードはすべて `@available(iOS 16.2, *)` の内側。
  弱リンクでないと iOS 15 の端末で起動時に落ちる。`tests/restNotifications.test.js` で縛ってある
- iOS 15・16.0/16.1 の実機(またはシミュレータ)での起動確認はまだしていない

## Xcode プロジェクトで触るときの注意

拡張ターゲット `RestActivity` は `xcodeproj` gem で追加した(Xcode GUI のテンプレートと同等の設定)。
**抜けてもビルドは通るが、Archive・アップロード・実機で初めて壊れる**設定が多いので、主なものは
`tests/restNotifications.test.js` の「休憩タイマーのネイティブ設定」で縛ってある。

- **版番号を上げるときは拡張もそろえる。** Xcode の General タブで App の Version / Build を上げても
  拡張は取り残され、アップロード時に弾かれる(ITMS-90473)。`MARKETING_VERSION` と
  `CURRENT_PROJECT_VERSION` は App・拡張の Debug/Release の4箇所で一致させる(テストで縛ってある)
- 拡張の `SKIP_INSTALL = YES` が無いと、Archive が「汎用アーカイブ」になり配布できない
- `Embed Foundation Extensions` は `[CP] Embed Pods Frameworks` より**前**に置く(後ろだと「Cycle inside App」)
- `RestTimerAttributes`(ActivityKit の型)は App と拡張の両方でコンパイルする共有ファイル。型名で照合されるので2つ作らない
- Podfile は `target 'App'` だけで、拡張は CocoaPods の対象外。`pod install` / `npm run ios:sync` は
  pbxproj を保存し直すので、実行後に拡張の設定が消えていないか `git diff` で見る(v112 時点では無変化を確認)
- `DEVELOPMENT_TEAM = LJR5Q5TU54` は App と拡張の4箇所。拡張の App ID
  (`com.hajime5150.kurabellplus.RestActivity`)の登録と Time Sensitive の capability 有効化は、
  **実機ビルドか Archive のときに自動署名が行う**(シミュレータでは確認できない)

## 検証のしかた(シミュレータ)

アプリは Xcode を AppleScript で Run して起動する(StoreKit Testing と同じ。docs/IAP実装方針.md)。
`xcodebuild build` + `simctl install` でも Live Activity と通知は動く。

- Time Sensitive: 休憩を開始してロックし、1分待つ。通知に「即時通知」のラベルが付けば効いている
- Live Activity: 休憩を開始して HOME → Dynamic Island の compact 表示。中央を長押しで expanded。
  LOCK でロック画面。初回は「ライブアクティビティを許可しますか?」が出る(iOS 標準の確認)
- stale 表示: `REST_ACTIVITY_STALE_MINUTES` を一時的に1にして確認し、必ず戻す
- ログ: `xcrun simctl spawn <UDID> log show --predicate 'process == "chronod" AND eventMessage CONTAINS "RestActivity"'`
  (受け取った `staleDate`、stale への切り替え、終了が見える)。`Activity.request` が失敗すると
  `[RestTimer] Activity.request failed:` が出る
