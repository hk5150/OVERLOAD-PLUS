# AIコーチ(1.4、手動版)

チャットAI(ChatGPT・Claude・Gemini など、設定で選んだもの)に、今日のメニュー(種目・順番・各セットの重量×回数)を組ませる。
相談文をコピーして AI を開き、返ってきた答えをアプリに貼り付けて取り込む。

元の検討: `~/Downloads/AI相談強化_ユーザーAPIキー_引き継ぎ.md`(2026-10-08、claude.ai のチャット)。
1.4 (16) の「次の一手」(規則の数字 + 端末内AIの言い換え)は「イマイチ」(北村さん、TestFlight)で、`c92490a` で外した。

## 決めたこと(北村さん、2026-10-08〜09)
- **数字を決めるのは利用者。** 案は一覧で見せるだけで、「この案を使う」を押したときだけ入れ替える。案に RIR は絶対に入れない(RIR が入る=実施済み)
- **アプリから AI へは何も送らない。** 相談文をコピーして AI のチャットを開くだけ(`privacy.html` の主張はそのまま)
- 入口は2つ:
  - 始める前: 今日のメニューのカードの「AIコーチに相談」。記録の無い Day では、今日の記録の空欄に出す
  - 記録中: 「今日の記録」の見出しの右と、種目一覧の最後(種目を足す欄の上)。残りを組み直してもらう。
    当初は左下の浮きボタンにしていたが、320px 幅でその高さのセット行の番号・重量欄に乗ったので、浮かせない形にした(北村さん、2026-10-09)
- 種目カードの「AI相談」は無くした。分割の Day の相談と、履歴の「AIに相談」は残している
- アプリに無い種目は取り込まず、知らせるだけにする。ウォームアップは AI の任意(`"wu":true`)
- プロフィール(目標・トレ歴・痛めている部位)は足さない(手動版なら、送る前に書き足せる)
- 自動版(ユーザーの API キーで端末から各社へ直接送る)は**まだ作らない**。手動版が使われるかを見てから決める。
  懸念は3つ:
  - 一般の人は API キーを持っていない(ChatGPT Plus と API の請求は別)
  - ヘルスケア由来の体重を外部の AI 会社へ送ることになる(5.1.2 / 5.1.3)
  - プライバシー申告の見直しが要る

## 仕組み
- 相談文: index.html の `coachPromptText(mode)`。`mode` は `"plan"`(始める前)か `"replan"`(記録中)。中身は次のとおり:
  - 私について(体重・単位・既定の目標回数)
  - 今日の分割(Day・対象部位・他の日の担当)
  - 種目ごとの直近3回の全セットと余力
  - 記録中は「今日ここまで」(RIR 入力済みのセットだけ)
  - 選べる種目の一覧(Day の部位に合うもの)
  - お願いと、取り込み用の形式
  - 重量は記録の値そのまま(ダンベルは片手、自重種目は加重分)。答えも同じ基準で書かせるので、`dayToText` のように実効重量へは直さない
- 答えの形式(コードブロック `kurabell`):
  `{"kurabell":1,"exercises":[{"name":"…","sets":[{"w":40,"r":10,"wu":true},{"w":60,"r":8}]}]}`
- 取り込み: `src/domain/aiCoach.js`(テストは `tests/aiCoach.test.js`)
  - `extractCoachPlan`: 答えの全文から、`exercises` を持つ JSON を探す。複数あれば、目印付きの最後のものを採る(相談文の見本ごと貼られても、AI の答えを採る)。寛容に読む:
    - 前後の説明文・コードブロックの有無
    - 全角・「“”」の引用符・末尾のカンマ
  - `makeCoachNameResolver`: 種目名を保存用の名前に引く。引けるものと順番:
    - 表示名に加えて英語名でも引く(日本語で頼んでも英語名で返す AI がある)
    - 空白・全角半角・括弧の違いは無視する
    - 括弧の中身ごと消して引くのは、それで見つからなかったときだけ
  - `validateCoachPlan`: 範囲外・読めない値のセットは捨てて数える。同じ種目の2回目は捨てる
  - `mergeCoachPlan`: 案を today に当てる(始める前は today = [])
- 始める前に取り込んだ案(`coachMenu`)は**メモリにだけ**持つ。日付か Day が変わったら使わない。
  カードに「前回の引き継ぎに戻す」が出る

## Watch との兼ね合い(記録中の組み直し)
Watch の入力は「種目の id + 行番号」で届く(`applyWatchOps`。セットに id は無い)。そのため `mergeCoachPlan` は次を守る:
- 案に残る種目は、今のカードの id を保つ
- 各種目の「最後の実施済みの行」までは一切触らず、その後ろだけを置き換える
  (案には実施済みを含めない約束で頼んでいる)
- 案に無い種目は、実施済みがあれば残し、無ければ外す
- 取り込む前に Watch のキューを合流させる(`drainWatchRef`)
- 「元に戻す」は5秒(`revertCoachPlan`):
  - その間にセットを終えた種目は、今のまま残す。丸ごと戻すと、その間に入れたセットが全種目で消える(reviewer 指摘)
  - 案で入った種目は、終えたセットがあれば残す
- 残る穴: 案で外した種目に、Watch がまだ古い一覧を見ていて入力すると、その入力は捨てられる(`applyWatchOps` は無い種目への op を捨てる)。
  組み直しの直後に、外れた種目を Watch で入れる場合だけなので、扱っていない
