## 13時のルーティンが止まる原因と、直したこと

無人の回は、許可の一覧に無い形のコマンドを打つと確認待ちになり、その日の回が終わらない。
これまでに止まったのは、`for … ffprobe`(10/31)、`mv`(10/27)、`curl`・`git show`(10/21)、Chrome の許可(10/24〜26)。
共通しているのは「その場で思いついた形のコマンド」なので、2026-10-31 に次のようにした。

- 確かめ用のコマンドを `marketing/tools/reel.sh`(durations・inspect・check・queue・files)にまとめ、許可の一覧に1行で入れた
- ルーティンの手順書(`~/.claude/scheduled-tasks/kurabell-marketing-pdca/SKILL.md`)に言い換え表を足し、手順の中の ffprobe・ffmpeg を reel.sh に置き換えた

## 公式 API で調べたこと(2026-10-31)

- **YouTube**: 審査を通していない Google Cloud のプロジェクトから `videos.insert` で上げた動画は、非公開に固定される。外すには YouTube API Services の監査(Audit and Quota Extension Form)が要る。
  分析(YouTube Analytics API)は監査なしで、本人の OAuth の同意だけで読める(視聴維持・平均視聴率)
- **TikTok**: Content Posting API は、審査前は投稿が非公開に固定され、さらに投稿先のアカウント自体が非公開でないと拒否される。
  審査は「広く一般向けのアプリ」が前提で、本人のアカウントだけに使う道具は通らないと複数の資料に書かれている(TikTok の原文は未確認)。
  審査前に非公開で上げた投稿は、審査が通っても公開にならない
- 審査を通った投稿代行サービス(Upload-Post など)の API を使えば、TikTok・YouTube とも無人で公開投稿できる。費用は月 $16〜24 前後(資料により違う。本人の申し込みが要る)
- TikTok Studio の予約は 10日先まで(複数の資料。公式のヘルプは未確認)
