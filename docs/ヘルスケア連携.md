# ヘルスケア(HealthKit)連携

iOS版だけの機能(v116〜)。Web版では設定の欄ごと出さない。

## 何をするか(2026-09-24 にユーザーと決定)

| | 内容 |
|---|---|
| ワークアウトの書き込み | 記録を保存したとき。種類 `.traditionalStrengthTraining`(日本語のヘルスケアでは「従来型筋力トレーニング」)・屋内、開始/終了時刻だけ |
| 体重の読み込み | 起動後と、画面が前面に戻ったとき。ヘルスケアの最新1件 |
| 体重の書き込み | 設定画面の体重入力からフォーカスが外れたとき |
| 既定 | オフ。設定のスイッチをオンにした時点で権限シートを出す |

**決めたこと(と理由)**
- **消費カロリーは書かない。** アプリの kcal は `5METs × 体重 × 時間` の推定値。Watch を着けたまま
  トレーニングする人は Watch が心拍から別に記録しているので、足すと二重に数えられムーブリングが実際より埋まる
- **過去の記録は書き込まない。** オンにした後に保存した分だけ。Watch で記録していた分と重なる恐れがあり、
  古い記録には `startAt` が無いものもある
- **アプリで記録を削除したらヘルスケアからも消す。** このアプリが書いた分だけが対象(HealthKitの仕様でも他アプリのデータは消せない)。
  バックアップの復元・全データ削除では消さない。連携がオフのときも消さない
- **4時間を超える記録は書かない**(`HEALTH_MAX_WORKOUT_MS`)。`startAt` は最初の種目を追加した時点で、下書きは
  24時間まで復元されるので、朝にメニューを組んで夜に保存すると「10時間の筋トレ」になる。実態と違う長さを
  ヘルスケアに残さない(Guideline 2.5.1)
- **連携のオン/オフと `healthBwAt` はバックアップの復元で上書きしない**(`keepDeviceHealth`)。
  「この端末で権限を取ったか」という端末固有の状態で、復元でオンになると権限シートを一度も出さないまま
  書き込みが黙って失敗し続けるため

## 紐づけのキー = `startAt`

記録には一意なIDが無い(配列の index で扱い、SQLite の `workouts.id` は保存のたびに `genId` で振り直される)。
IDを新設すると SQLite スキーマの変更 = シミュレータ必須の移行作業になるので、保存後に変わらない `startAt`(ISO文字列)を使う。
SQLite(`start_at`)・JSONバックアップを往復しても残り、履歴の編集では変わらない(日付を変えるUIが無い)。
**履歴に日時を編集する機能を足すときは、ヘルスケアの紐づけが切れる**ので、ここを見直すこと。

HealthKit 側には `HKMetadataKeySyncIdentifier = "kurabell-workout-<startAt>"`(+ `SyncVersion = 1`)を付ける。
削除はこの値と `HKSource.default()` の述語で `deleteObjects`。
履歴の編集で変わるのはセットと総ボリュームだけで、書き込んだ項目(時刻)は変わらないので、編集時の同期はしない。

## 体重の同期(書き戻しのループを起こさない)

`profile.healthBwAt` = 最後にヘルスケアと体重を同期した日時(エポックミリ秒)。

- 読み込み: ヘルスケアの最新サンプルの日時が `healthBwAt` より新しいときだけ反映(`pickHealthWeight`)。0.1kg に丸める
- 書き込み: 保存したサンプルの日時を `healthBwAt` にする → 次の読み込みで自分の書いた値を拾い直さない
- 入力は1文字ごとに保存されるので、書き込みは `onBlur` だけ。編集前との差が 0.05kg 未満・20〜400kg の範囲外は書かない
- 手入力したら、書き込みの成否や連携のオン/オフによらず `healthBwAt` を進める(失敗・オフなら今の時刻)。
  手で入れた値を、その時点より古いヘルスケアの値(体重計アプリが後からまとめて同期した分など)で上書きしない
- 体重欄にフォーカスしている間は読み込まない。入力途中の値が差し替わり、離れたときにその値を書き戻してしまうため

**初めてオンにしたとき**は `healthBwAt = 0` なので、ヘルスケアの最新の体重を日付に関係なく取り込む
(何年も前の値でも)。設定画面を見ている最中に値が変わるので気づける、として許容した。

## 実装の場所

- ネイティブ: `ios/App/App/Health/`(`HealthPlugin.swift` がブリッジ、`HealthManager.swift` が本体)。
  `BridgeViewController` で明示登録、`App.entitlements` に `com.apple.developer.healthkit`
- 権限ダイアログの文言: `Info.plist`(英語)と `ja.lproj/InfoPlist.strings`(日本語)。
  UI は WebView 側で言語を切り替えるが、この文言だけは OS が出すので .lproj が要る
- `UIRequiredDeviceCapabilities` に `healthkit` は入れない(入れると対応端末が絞られる)
- JS: `src/domain/health.js`。失敗はすべて握りつぶす(記録の保存を妨げない)
- `index.html`: `defaultProfile` の `healthOn`/`healthBwAt`、`saveWorkout`・`deleteWorkout`・編集で空になったときの削除、
  体重の読み込み effect、設定画面の欄
- ヘルスケアの応答を待ってから `persist` する経路は `persistRef`/`profileRef` で最新を参照する
  (await の前に捕まえた `persist` を呼ぶと、その間に変わった workouts 等を古い値で上書きする)。
  ただし ref が更新されるのは描画のときなので、全削除や復元の直後、描画前の数ミリ秒にヘルスケアの応答が
  届くと古い `persist` を呼びうる(reviewer 指摘、未対策)。根本的には `persist` が最新の状態を ref に
  同期的に持つ形に変える必要があり、既存の全経路に関わるので別の作業にした

## 検証(2026-09-24、iPhone 17 Pro Max シミュレータ / iOS 26.5)

- 権限シートに日本語の説明文が出る → 許可 → スイッチがオン
- 体重 73 を入力して離れる → ヘルスケアに 73.0kg が1件。入力途中の `725`(範囲外)は書かれない
- 記録を保存 → ワークアウト1件(activity_type 50 = traditionalStrengthTraining、屋内、開始/終了時刻)。消費カロリーのサンプルは無い
- 履歴から削除 → ヘルスケアのワークアウトも消える
- ヘルスケアアプリで体重を 74kg に → アプリに戻ると設定の体重が 74 になる。書き戻しは起きない(サンプルは2件のまま)

シミュレータのヘルスケアのデータは `~/Library/Developer/CoreSimulator/Devices/<UDID>/data/Library/Health/healthdb_secure.sqlite`
をコピーして sqlite3 で読める(`samples.data_type` 3 = 体重、79 = ワークアウト、`workout_activities.activity_type`)。

**未検証**
- 書き込みを拒否したときの案内文(シミュレータで権限を戻す手段が無い。`simctl privacy` は health を扱えない)
- 実機のフィットネスアプリでの表示、Watch で別に記録したワークアウトとの並び方
- 同じ syncIdentifier で二度書いたとき本当に1件のままか(UIからは二度書けない)

## 提出時にやること

- App ID に HealthKit の capability(自動署名なら初回の実機ビルド/Archive で付く)
- `APPSTORE.md`: 説明文に「ヘルスケア連携」を明記(Guideline 2.5.1)、審査メモに使いみち。
  App Privacy は「収集なし」のまま(ヘルスケアのデータも端末外に送らない)
- `privacy.html` はヘルスケアの節を追加済み(v116)
