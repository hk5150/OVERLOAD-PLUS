# 次の一手(1.4 予定、ブランチ `v1.4`)

種目ごとに「次にやる重量・回数の案」と、その理由を出す。元の検討は `~/Downloads/AI提案_FoundationModels.md`(2026-10-08、claude.ai のチャット)。

## 決めたこと(北村さん、2026-10-08)
- **数字は規則で決め、端末内AIには理由の文章だけを書かせる。** Apple 自身が端末内モデルについて「基本的な算数・論理推論は避けるべき」と書いている
- 使うのは **Apple Foundation Models の端末内モデル(`SystemLanguageModel`)だけ**。Private Cloud Compute と外部プロバイダー(Claude・Gemini)は、記録が端末の外に出るので使わない(`privacy.html` の「外部へ送らない」とぶつかる)
- 対象は種目ごとの重量・回数だけ。試用中(記録10回まで)も使える。**ボタンを押したときだけ**出す。既存の「AI相談」(クリップボード)は残す
- **案を並べるだけで、記録は自動で書き換えない。** 「この案で入れる」を押したときだけ、まだ RIR を入れていない本番セットに入れる(実施済み・ウォームアップは触らない)

## 仕組み
- 規則: `src/domain/nextStep.js` の `suggestNextStep`(ダブルプログレッション。材料は `exerciseInsight` と種目の repLow/repHigh/increment)。
  分岐は 増量(上限回数・RIR≥1)/ 据え置き(上限回数・RIR0)/ 回数+1 / 回復(回数が落ちている最中)/ 加重しない種目。重量は表示単位で計算する
- 画面: 種目カードの判断材料の行の「次の一手 ›」→ パネル(案・理由・「この案で入れる」)。Web 版も規則と定型文で出る
- 端末内AI(iOS のみ): `ios/App/App/Ai/AiPlugin.swift`(jsName `Ai`、`availability` / `explain`)。`#if canImport(FoundationModels)` +
  `#available(iOS 26.0, *)`。デプロイ対象は 16.2 のまま。使えないとき(iOS 26 未満・非対応機種・Apple Intelligence オフ・未 DL)は定型文だけ
- AI の文は、定型文を先に出しておいて届いたら差し替える。**案に無い数字が入っていたら捨てる**(`aiTextIsConsistent`)。失敗・10秒の時間切れも定型文のまま

## 端末内モデルを試して分かったこと(2026-10-08、Mac 上の同じモデル)
- 例なしの指示だと、**事実と違う説明を作った**(据え置きの案に「前回の80kg×8回より少し軽いので」)。英語では見出しを並べるだけだった。
  → 指示に例を2つ入れ、渡す材料を「案+理由」の1行に絞ったら、日英とも案どおりの自然な一言になった
- **「自重 × 16回」(加重しない種目)の入力は、毎回 guardrailViolation(安全機能の誤検出)で止まった。** 定型文に落ちるので実害はない
- 数字は一致していても、言い換えで事実の一部(「余力がなかった」)を落とすことがある。数字の検証だけでは防げない
- 価値は「言い回しが自然になる」程度。**実機(TestFlight)で北村さんに質を見てもらい、物足りなければ AI の文はやめて定型文だけにする**判断もありうる
