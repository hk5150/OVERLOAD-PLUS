## 1. お疲れ様の画面で「前回と比べた結果」を見せる

### 出すもの
総ボリュームの下(今の「過去3回平均」の行の位置)に、3つの数を横に並べる。

```
前回と比べて
  ▲ 6セット     = 7セット     ▼ 2セット
  前回超え        同じ          下回り
```

- 色はセット行の差分と同じ(▲ 緑 / = 灰 / ▼ 黄)。黄は「注意」の色で、赤は使わない(`docs/画面改善.md` の色の役割)
- その下に1行、**今日いちばん伸びた種目**を1つ:「ベンチプレス +2.5kg」「懸垂 +2回」。伸びた種目が無ければ出さない
- 比べられるセットが1つも無い日(全部が初めての種目)は、この欄を出さず、今の「次に {Day} をやると…」の一文を出す(今と同じ)

### 数え方(セット行の差分と1件も食い違わないこと)
セット行の右に出る差分(`index.html` の `delta`、`+2.5kg` / `+1回` / `RIR+1` / `同じ` / `−2.5kg` …)と**同じ規則**で数える。
画面で緑だったセットの数と、ここの「前回超え」の数が合わないと信用されないため。

1. 対象は、保存した記録のワーキングセット(ウォームアップを除く)
2. 比べる相手は、その種目の前回の記録の**同じ番手のワーキングセット**(`exerciseInsight(...).sets[wsIndex - 1]`。別の Day でやった前回でもよい。今のセット行と同じ)。相手が無いセットは数えない
3. 補助ありと補助なしは比べない(数えない)
4. 重量 → 回数 → RIR の順に、最初に違うところで決める
   - 重量は**表示単位の数字どうし**で差を取り、0.1 に丸めて 0 なら同じ(lb の人に「+0lb」が出ない、今の規則)
   - 重量が増えて回数が減ったセットも「前回超え」(セット行で緑になるのに合わせる)
   - 重量・回数とも同じで RIR が増えた(余力が増えた)ら超え、減ったら下回り、同じなら「同じ」

この規則を `src/domain/` の純粋関数にして(`insight.js` の `compareWithPrevious(exercises, prevSetsOf, opts)` →
`{ up, same, down, best }`)、**セット行の差分もこの関数から取るように寄せる**。2か所に同じ規則を書くと、片方だけ直したときに
食い違う(係数の解決を `resolveCoefficients` に一本化したのと同じ理由。CLAUDE.md「ドメインの約束事」)。

`best`(いちばん伸びた種目)の選び方: 重量が増えた種目を優先し、増えた重量の割合が最大のもの。重量が同じなら回数の増え。
同じ値なら記録の並びが先のもの。

### 今ある行の扱い
- 「過去3回平均まで あと○kg」(届かなかった日)は、お疲れ様の画面では**出さない**。記録中の上部バーには今どおり出す
- 届いた日の「過去3回平均 +○kg」は、3つの数の下に小さく残す
- 「1RM更新」の欄は今のまま(自己ベストは別の意味の勝ち)

### 他への影響
- **Watch**: お疲れ様の中身(`finishedSummary`)は Watch にも送っている。数を `compare: { up, same, down }` として足す。
  `WatchModels.swift` の `Finished` は Codable なので、知らないキーがあっても読める(Watch 側の表示を変えるのは別の回でよい)
- **投稿用の画像**: 「前回超え 6セット」を入れると投稿の中身が強くなる。ただし画像の作り直しは手間が大きいので、2回目の版に回す
- **英語**: 「vs last time ▲ 6 sets = 7 ▼ 2」。i18n の日英の対応はテストで縛ってある
- **レビュー依頼**: 今は「推定1RMを超えた種目があるとき」(`beatPrevious`)。「前回超えが1セット以上」に広げると依頼の機会が増える。
  ただし Apple の上限(365日に3回)と120日に1回の制限はそのまま。広げるかは北村さんの判断(下の「決めてほしいこと」)

## 2. 週の目標と、続いた週の数

### 決めるもの
- `profile.weeklyGoal`(1〜7 の整数、未設定は null)と、既にある人に1回だけ聞いたかの `profile.weeklyGoalAsked`。バックアップにも入る(profile ごと)
- 初回の「週に何回?」で型を選んだとき、型に合わせて入れる:
  全身法(週1〜2回)→ 2 / 上半身・下半身(週2〜4回)→ 3 / PPL(週3〜6回)→ 3 / 5分割(週5回以上)→ 5
- 既にある人(分割を作り済み・目標なし)は、分割タブの上に1回だけ「週の目標を決めましょう」と出し、
  直近4週の平均回数を四捨五入した数(1〜7に収める)を最初から選んだ状態にして、押すだけで決まるようにする。✕ で閉じたら2度と出さない
- 設定タブ(体重の下)で 1〜7 から変えられる。「なし」にもできる(出さない)

### 数え方
- 週は**月曜始まり**(履歴の「週別」のグラフ(`index.html` の `dow = (d.getDay() + 6) % 7`)と同じ。カレンダーの表示は日曜始まりのまま)
- 「今週の回数」は、今週保存した記録の数。同じ日に2回保存したら2回(分けて保存するのは本人の意思なので)
- 「続いた週」は、目標に届いた週が、先週から何週さかのぼって切れずに続いているか。**今週は、届いた時点で数に入れる。
  届いていない今週は数えず、切れたことにもしない**(週の途中で「連続が途切れた」と見せない)
- 目標を変えたら、過去の週も新しい目標で数え直す(週ごとの目標の履歴は持たない。持つと保存するものが増えるわりに得が小さい)
- 純粋関数にする(`insight.js` の `weekProgress(workouts, goal, now)` → `{ thisWeek, goal, streak, reached }`)。週の境目・年またぎ・
  夏時間の無い日本でも端末の時刻で区切ることをテストで縛る

### 出す場所
1. **分割タブの一番上**(起動時に開くタブ)。1行で:
   `今週 1 / 3回   ● ○ ○   3週連続`
   丸は目標の数だけ並べ、済んだ分を塗る。目標が7を超えることは無いので折り返さない。目標が null の人には出さない
2. **お疲れ様の画面**の「次は Pull」の欄に1行足す:「今週 2 / 3回目」。この保存で目標に届いたら「今週の目標を達成 · 4週連続」(緑)
3. Watch・ウィジェット・通知の文面には、この回では入れない

### 今あるものとの関係
- トレーニング日のお知らせ(`docs/UIレビュー_2026-10.md` の A3-2)は今のまま。目標の回数と曜日の数を揃えたくなるが、
  曜日を選ぶ人と回数で考える人がいるので結びつけない
- 「直近7日間の部位別」(分割タブ)は今のまま。今週の行はその上に置く

## 実装メモ(2026-11-11、1.4.8)
計画からの変更と、計画に書いていなかったところで決めたこと。

- **セット行の置き換えの確かめ方**: 置き換え前(`737254c`)と後を並べて Playwright で開き、同じ記録(重量増・回数増・RIR 増減・同じ・
  重量増で回数減・未実施・補助の混在・前回 RIR なし・lb の刻み 77.5kg=171lb・62.3kg の端数)のセット行の文字を、日英 × kg/lb の4通りで
  全行比べて一致した。スクリーンショットの目視ではなく文字で比べた(色は同じ `kind` から決めている)
- **差分の規則の置き場**: `setDelta(cur, prev, conv)`。`conv` は `{ toDisplay: wU, fromDisplay: fromU, snap: snapKg }`(`index.html` の
  `UNIT_CONV`)。文言にするのは `index.html` の `setDeltaText`(セット行と、お疲れ様の「いちばん伸びた」の重量で共用)
- **お疲れ様の数は保存前の `today` から数える**(保存した記録からではない)。保存すると未実施の行が落ちて番手がずれ、セット行と食い違うため。
  相手は保存前の履歴の `exerciseInsight(name).sets`(セット行と同じ)
- **いちばん伸びた種目**: 「いちばん伸びた: ベンチプレス +2.5kg」/「Biggest gain: … +5.5lb」。回数は「+2回」/「+2 reps」。
  前回の重量が 0(自重に加重を足した)ときの割合は 100% とみなす
- **見た目**: 3つの数は Barlow の大きな数字に ▲ / = / ▼ を添える。0 のときは灰色。届いた日の「過去3回平均 +○kg」はその下に 12px の緑
- **週の目標のカードは、分割があるときだけ出す**(計画は「記録が1回以上」だけ)。分割が無い人の分割タブは「週に何回?」の型選びなので、
  同じ問いが2つ並ぶ。分割の無い人は型を選んだときか、設定で決める
- **連続は2週目から出す**(「1週連続」は出さない)。分割タブの丸は、届くまで黄、届いたら緑
- **お疲れ様の「今週 n / 目標回目」は、この記録が今週に数えられたときだけ出す**。購入の前で止めた先週の記録を今週保存したときは出さない
- **設定は `<select>`**(なし・週1回〜週7回)。設定で変えたら `weeklyGoalAsked` も true にする(カードを後から出さない)
- **回数が空(0)の行は数えない**。保存のときに落ちる行なので、RIR だけ入っていても「下回り」にしない(セット行には今どおり差が出る。reviewer 指摘)
- **型から目標を入れるのは `weeklyGoalAsked` が false の人だけ**。設定で「なし」にした人やカードを ✕ で閉じた人が、分割を削除して型を選び直したときに目標を入れない(reviewer 指摘)
- **バックアップの読み込みで `weeklyGoalAsked` は戻さない**(`keepDeviceHealth`)。1.4.8 より前のバックアップを読んでもカードを出し直さない(reviewer 指摘)。目標の値はバックアップのものになる
- **シミュレータ**: 自分用の「KURABELL 1.4.8 check」を作り、Preferences に `simctl spawn … defaults write` で記録を入れて撮った(plist を直接書くと cfprefsd のキャッシュに負けて読まれず、初回ガイドが出た)。
  分割タブのカード(日本語)と「This week 2 / 3 ●●○ 2-week streak」(英語・lb)を確認。シミュレータを指で操作する許可が無かったので、お疲れ様の画面は
  iOS と同じ事前ビルド(`www/`)を Chromium で開いて、保存までの流れを日本語kg・英語lb で確認した
- Watch(Swift)は触っていない。`finishedSummary.compare` は Watch の `Finished`(Codable)が読み飛ばす
