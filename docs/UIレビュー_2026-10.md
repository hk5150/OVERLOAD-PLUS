# UI レビュー(2026-10-18)の実装

提案の本文と撮影した画面は、プロジェクトの共有フォルダの `ux-review-2026-10-18/README.md`(北村さん「上位1から4と提案してもらった全て対応してください」)。
見立ては「アプリの価値(前回の記録が横に並ぶ)は同じ Day の2回目で初めて見える。1回目を迷わず終えて、2回目に戻ってくるまでを短くする」。

## 決めたこと
- **A1 初回の種目は 0kg × 0回 を3行**(`FIRST_TIME_SETS`)。入力しなかった行は RIR が無いので未実施として捨てられる。メニューは「初回」バッジ +「重さを決めて記録(3セット)」
- **A2 記録前は「この内容で記録を開始」が主役(黄)、AIコーチは灰色**。記録中はセッションのカードを1行に畳み、バックアップの帯も出さない(保存の後に出る)
- **A3-1 お疲れ様の画面に「次は Pull」**。記録が少ないうち(その Day の1回目、分割なしなら最初の1回)だけ「次にやると横に並ぶ」の一言。通知が使える端末でリマインダーがオフなら設定への導線
- **A3-2 トレーニング日のお知らせ**(設定タブ、ネイティブだけ)。端末内のローカル通知で、アプリから何も送らない方針は崩れない。
  - 28日先まで1回ずつ予約する(繰り返し予約にしないのは、その日にもう保存していたら知らせないため)。ID は 5100〜5127(休憩は 4200〜4215)。起動・保存・設定変更のたびに積み直す
  - 文面は「今日は Push の日。前回 ベンチプレス 77.5×9」
  - 初めてオンにしたときは、直近28日で2回以上やった曜日と、いちばん多い開始時刻を入れる。一度選び直した曜日・時刻は、オフ→オンしても上書きしない
- **A4 前回の数字は本文と同じ色・太さ**。日数はセッションのカードに出し、行には、メニューで一番多い日数と違う種目にだけ出す(その日数が上の部位の行に出ていないときは省かない)
- **B1 ボリューム推移の既定は「Day別」**(分割で記録がある人)。分割が無い人は今までどおり「トータル」
- **B2 履歴の各日は畳む**。開くのは、最新の日・カレンダーで選んだ日・編集中の日だけ。開閉は記録の date で覚える。自己ベストは「履歴」の上へ移し、最近更新した順に5種目、残りは「すべて表示」。「未更新」は30日以上のときだけ。ダンベルは「片手 29.0kg」も添える(C5)
- **B3 購入画面**: 見出しは「無料の10回を使い切りました」で、10回の成果(自己ベストの更新回数・総ボリューム)を出す。試用の残りは残り7回(4回目の記録)から出す。
  - **11回目は今までどおり保存の前に止め、その日の下書きを残す**(北村さんの判断、2026-10-18)。下書きは24時間で消さず、購入して保存するか、消すまで残る(下書きの `keep`)
  - `keep` には保存を止めた時刻が入っていて、何日か後に購入して保存しても、記録の日付・時間・kcal はその時刻で締める(レビューで見つかった。そのままだと購入した日の記録になり、時間が数千分になった)。休憩の時計は戻さない
- **B4 RIR を入れて休憩のパネルが出たら、次のセット行がパネルの上に見えるところまで送る**
- **C1 分割タブ**: ローテーションの説明は記録が1回以上あるときだけ。「分割を削除」は「変更 / 作り直す」の中の一番下。空の Day が2つ以上あれば「N日分をまとめておまかせで入れる」を1つ(Day ごとのおまかせは灰色)
- **C2 直近7日間の部位別で、減った量は灰色**(赤は主要操作と削除の色)
- **C3 初回ガイドは4ページ**(ようこそ / 分割 / 前回と比べる(RIR の説明込み) / AIコーチと Watch)。画像 `guide/*-1〜3.jpg` は 2026-10-18 の画面で撮り直した。`*-4〜6.jpg` は使っていないが、テストと `APP_ASSETS` が1〜7を前提にしているので残した
- **C4 版番号は設定タブの一番下**(`tests/version.test.js` の文言も合わせた)

## 確かめたこと
- `npm test`(887件)。Web 版(8765)を Playwright で 390×844、日英で開き、初回の流れ・2周目(PPL 12回)・休憩パネル・お疲れ様・履歴・設定を撮った。ページのエラーは無し
- リマインダーは `window.Capacitor` の偽物を入れて、設定の表示と予約の中身(12件、ID 5100〜、文面)を確認
- 止めた下書き(`keep`)を3日後に開いて保存し、日付が止めた日・時間50分のまま入ることを確認

## シミュレータで確かめたこと(2026-10-18、iPhone 17 Pro・iOS 26.5、初回の状態から)
- 頼んだ項目はすべて動いた。B4 は1・2セット目とも二重に送られない。リマインダーは許可ダイアログ→曜日・時刻と出て、指定の時刻に通知が届いた
- 見つかった崩れと直し方:
  - お疲れ様から設定へ飛ぶと、欄の見出しが画面の上に隠れた → `scrollIntoView` + `scroll-margin` をやめ、ノッチ帯の目隠し(休憩中は上部バー)の高さを実測して `scrollTo`
  - お疲れ様の画面とガイドの背景が半透明で、後ろの文字が透けた → 不透明に
  - Day別の縦軸が「1.1k」を何段も並べた(値の幅が狭いとき)→ 幅が 2,000 より狭ければ丸めずに出す
  - ガイドの文(「前回 24×11 RIR1」)が撮り直した画像と違った。本文の長さで「次へ」が上下に動いた → 文を画像に合わせ、本文だけスクロールさせてボタンを固定。背の低い画面では画像を小さく
  - 記録が無い人の「今日のメニュー」に「記録をそのまま引き継いでいます」と出た → 全部が初めての種目なら別の一文
  - タブを替えても前のタブのスクロール位置のままだった → タブごとに覚えて戻す(初めて開くタブは上から)
- 2回目の確認(同日)で残っていたもの:
  - 保存した後の記録タブが下端から出た(覚えた位置を消しても、タブを替えるときに覚え直していた)→ 「次に覚えない」印を付ける。分割タブで Day を選んだ後の記録タブも同じ
  - メニューの下の「記録を開始」から始めると、3種目目あたりから出た → 始めたら上へ
  - 保存した直後の履歴で、Day別が次の「今日」の Day(記録1回でグラフ無し)を選んでいた → 最後に記録した Day を選ぶ
  - ガイド3・4ページの本文の最後がスクロールしないと読めなかった → 本文を短くし、画像と余白を詰めた(iPhone 17 Pro・16 相当の高さで収まる。SE の高さではスクロール)
- 休憩パネル+キーボードで上部バーが隠れる件は、main(8063189)のビルドでも同じだった。今回の変更で起きたものではない

## 残っていること
- 休憩パネルを出したまま重量の欄を押してキーボードを出すと、上部バーが半分ステータスバーの裏に入り、休憩パネルの数字がキーボードの上の帯に隠れる(main でも同じ。別の改善として扱う)
- 休憩の通知は、アプリを前に出している間もバナーで出る。通知の許可ダイアログは、設定より先に最初のセットの休憩で出る(休憩の通知が最初からオンのため)
- B4 はスーパーセットのとき、DOM 上の次の行に送る(次にやるセットとは限らない)
- 履歴を編集して前回の数字が変わっても、リマインダーの文面は次の起動・保存まで古いまま
- **lb で使うと、前回と同じ重量でも「自己ベスト」が出る**(今回の変更とは別の、前からの不具合)。77.5kg が入力欄で 171lb に丸められ、保存のときに 77.56kg に戻るため。英語のガイド画像は kg で撮った
- 版(CACHE / APP_VERSION)は上げていない。iOS のビルドの前に、印を作ってから上げる
