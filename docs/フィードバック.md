# ユーザーの声を集めて改善に回す仕組み(2026-10-18〜)

北村さんの依頼「ユーザーからのフィードバックの仕組みづくり」の記録。

## 始めたときの状態(2026-10-18)

- アプリ内に問い合わせの導線が**無かった**。宛先は `support.html`・`privacy.html`(App Store の掲載ページから辿る)にしか書いていない
- 評価依頼はある(`src/domain/review.js`、前回を超えた保存の後、記録3件以上・120日に1回、iOS が出すかを決める)
- App Store のレビューは `scripts/asc/reviews.mjs` で読め、12時のルーティンが新着を報告している
- Gmail に利用者からの意見は0件(届いていたのは ASO の営業メール1通だけ)

## 集める入口(3つ)

| 入口 | どう集まるか | 誰が拾うか |
|---|---|---|
| アプリ内「ご意見・不具合の報告」(設定タブ) | メールアプリが開き、件名 `[KURABELL] …`・本文末尾に版/iOS/言語/単位 | Gmail。件名 `[KURABELL]` で振り分け |
| App Store のレビュー | アプリ内「App Store でレビューを書く」+ 既存の評価依頼 | 12時ルーティン(`reviews.mjs --json`) |
| SNS のコメント・DM | Instagram / TikTok / YouTube | 13時ルーティン(コメントは API で読める範囲) |

## アプリ内の導線(このブランチで実装)

- 設定タブのバックアップの下に「ご意見・不具合の報告」カード。「メールで送る」「App Store でレビューを書く」(iOS 版だけ)「宛先とコピー」
- **アプリからは何も送らない。** `mailto:` でメールアプリに下書きを渡すだけ。本文に入れるのは版・iOS の版・言語・単位だけで、
  記録や体重は入れない(`tests/review.test.js` で縛ってある)。App Store の「Data Not Collected」申告は変えない
  (利用者が自分で送る問い合わせは Apple の「任意の開示」の扱い)
- 既定のメールアプリ(Gmail などを既定にしていればそれ)が開く。Mail を消して既定も無いと「メールを復元」の確認が出るだけなので、PC から送りたい人の分も含めて宛先のコピーを並べた
- 件名の頭は言語によらず `[KURABELL]`(Gmail のフィルタ用)
- レビューの URL は `https://apps.apple.com/app/id6816090624?action=write-review`(App Store アプリの「レビューを書く」画面が開く)
- 「評価する前に満足度を聞いて、不満な人だけメールへ回す」は**やらない**(Apple のガイドライン 5.6.1 が独自の事前確認を嫌う。レビューの選別になる)

## 改善に回すしかた(2026-10-18 から動いている)

1. 集めた声を1行ずつ台帳(Obsidian の `Projects/kurabell-feedback.md`)に入れる(日付・入口・要約・分類[不具合/要望/使い方の質問/称賛]・状態[未検討/採用/見送り/済(版)])
2. 週に1回、未検討を北村さんが採用/見送りに振り分ける。採用したものは `docs/改善要望_*.md` と同じ形で検討する
3. 出した版で直ったら、送ってくれた人に返す(メールは北村さん、App Store のレビューへの返信は `reviews.mjs reply`、どちらも確認を取ってから)
